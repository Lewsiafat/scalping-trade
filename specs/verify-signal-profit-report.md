# 高等級建議獲利驗證報告（基準 2026-07-10）

> 核心問題：**當系統觸發高等級投資建議時，給出的入場價 + SL/TP 是否真的賺得到錢？**
> 答案：**目前賺不到錢。** A 級建議（strong + confirmed + R:R good）44 筆，勝率 20.5%、期望值 -0.782R（95% CI [-1.23, -0.33]，顯著為負）、平均每筆 -0.258%。全系統 1,691 筆事件無任何等級為正期望（整體勝率 34.2%、PF 0.24、累計淨 -279.8%）。

## 一、驗證機制

新增 `verify_signal_profit.py`（V1.0）——逐訊號事件研究（event study），與 `app_backtest.py` 的組合回測互補：

| | app_backtest.py | verify_signal_profit.py |
|---|---|---|
| 衡量對象 | 「策略」績效（持倉互斥） | 「建議本身」的品質（每筆訊號獨立模擬） |
| 等級欄位 | 未記錄 | 每筆事件完整記錄 overall / signal_stage / rr_grade / 3D 分數 / composite / label |
| 分層統計 | 無 | by_tier / by_label / by_direction / by_symbol / by_rr_grade |

機制要點：
- **等級分層**：A = strong + confirmed + RR good；B = strong + confirmed + RR acceptable；C = 一般(buy/sell) + confirmed；D = 有訊號無 pre-alert；E = 謹慎進場（caution RR）。
- **結局模擬**：全倉 TP1 出場制，同 bar 同觸 SL/TP 以開盤價判定、模糊時保守判 SL（與 app_backtest 一致）；記錄 MFE/MAE（R 倍數）。
- **成本模型**：來回手續費 0.1% + 進場滑價 0.05%（可調）。
- **去重**：同方向 6-bar 冷卻（模擬即時系統重複觸發）。
- **無 look-ahead**：MTF 切片只取已收盤 K 線（修正了 app_backtest 的輕微 look-ahead）。
- **分頁抓取**：突破單次 1000 根上限，樣本擴至 5000 根（5m ≈ 17.4 天）。

用法：
```bash
python3 verify_signal_profit.py --symbols BTCUSDT,ETHUSDT --interval 5m --bars 5000 \
    --max-hold 144 --cooldown 6 --fee 0.1 --slippage 0.05 --out result.json
```

## 二、基準驗證結果

範圍：BTC/ETH/SOL/BNB/XRP/DOGE × 5m × 5000 根 + BTC/ETH × 15m × 3000 根，共 1,691 筆事件。基準數據：`backtest_results/baseline_20260710/`（未進 git）。

### 按等級分層（核心結論）

| 等級 | n | 勝率 | PF | 期望值 (R) | 均淨損益 |
|---|---|---|---|---|---|
| A（最高等級） | 44 | 20.5% | 0.26 | **-0.782** | -0.258% |
| B | 999 | 35.1% | 0.22 | -0.625 | -0.154% |
| C | 612 | 33.0% | 0.25 | -0.676 | -0.176% |
| D（無 pre-alert） | 36 | 44.4% | 0.42 | -0.424 | -0.194% |
| E | 0 | — | — | — | — |

統計判讀（已對抗性覆核）：
- **每一級都顯著為負**；「全系統負期望」極穩健（t=-30.4）。
- 「A 級墊底、D 級最好」是點估計；tier 之間的期望值差異**不顯著**（A vs B t=-0.68）。統計上站得住的是：A 級勝率顯著低於 B 級（z=-2.00）、rr_grade=good 勝率顯著低於 acceptable（22.0% vs 34.6%，z=-2.36）。
- 等級分數無鑑別力：composite/quality/min_floor 與 net_pnl 的相關係數僅 +0.02~+0.03；最嚴格組合（composite≥70 且 min_floor≥45，n=213）仍 -0.138%/筆。**問題不在閾值位置，是分數本身無預測力。**

### 錢從哪裡漏掉

1. **賠付比失衡**：TP1 中位距離 0.16% < SL 中位 0.255%；tp1 出場實得僅 +0.208R、SL 出場 -1.398R → 打平需 76–87% 勝率，實際 34.2%。名目 rr_ratio（以 TP1 計，`app_v3.py:1795-1798`）平均 1.08，滑價後實現僅 0.657——±0.05% 滑價對 0.16–0.26% 的微距離扭曲巨大。
2. **摩擦成本致命**：0.15% 來回摩擦佔平均 TP 距離 68%、佔中位 SL 距離 59%；794 筆打到 TP1 的單有 216 筆（27.2%）扣費後仍淨虧；1,691 筆共繳約 169% 費用（毛 -110.7% → 淨 -279.8%）。
3. **訊號本身無正向 edge**：零摩擦口徑整體仍 -0.0155%/筆（CI 勉強排除零；佔 59% 樣本的 B 級 CI 含零、與打平無異）。結論：**摩擦是主要虧損來源，但訊號也沒有正 edge 可供攤提摩擦**。
4. **進場偏早**：獲利單 40.1% 曾浮虧 ≥0.5R（mae_r 中位 0.433）；SL 單僅 11.5% 曾到過 +0.5R。

### 其他重大發現

- **signal_label 退化為死代碼**：1,691 筆 100% 為「Sweep 確認」，OB 反彈/壓力、FVG 支撐/阻力、指標共振從未出現，優先序無法驗證。
- **低價幣訊號生成失效**：DOGE 4,850 根 bar 產生 0 筆事件、0 筆 suppressed（連 pre-alert 都沒觸發）；XRP 僅 9 筆且平均 SL 距離 1.105%（其他幣 0.22–0.42%），尺度異常。
- **訊號密度過高**：5m 主流幣每天 17.7–21.4 筆已執行事件，59.6% 原始觸發被 6-bar 冷卻壓抑，相鄰事件中位間隔僅 45–50 分鐘（同一掃蕩區反覆觸發）。
- **多空已對稱**（v4.2.2 修復確認生效）：long 832 / short 859 筆，但雙向皆虧。
- **可借力的方向性線索**：SOL_5m 是最佳大樣本切片（PF 0.39）；BTC 5m→15m PF 0.09→0.28；SL 距離越寬、摩擦佔比越低、PF 越好（XRP SL 1.105% → PF 0.89 最接近打平）。
- **量測層注意**：同 bar 同觸保守判 SL 會系統性壓低勝率（平均持倉僅 3.6–4.6 根、TP 距離極小，同觸頻繁），影響結論幅度但不至於翻轉（需樂觀口徑敏感度測試定上界）；timeout 僅 2 筆，max_hold=144 形同虛設。

## 三、後續改進目標

每項改動後一律用 `verify_signal_profit.py` 對同樣 8 檔重跑，與 `backtest_results/baseline_20260710/` 對照。

### P0（bug 與結構性修復）

1. **修復 signal_label 退化與低價幣失效**
   依據：100% 訊號都是「Sweep 確認」（其他五類 n=0）；DOGE 0 事件 0 suppressed；XRP SL 尺度異常。檢查 `determine_signal_label` 優先序（有 Sweep 就短路）與低價幣（<$3）的 ATR/結構偵測是否有精度/絕對值門檻失準。
   驗收：by_label 至少出現 3 類且各 n≥30；DOGE 密度 >5 筆/天；XRP SL 距離回落 0.2–0.5%。

2. **修正 TP1/SL 距離不對稱與淨 R:R 門檻**
   依據：TP1 中位 0.16% < SL 中位 0.255%；tp1 實得 +0.208R；27.2% 打到 TP1 仍淨虧。`calc_dynamic_sl_tp` 改以「扣除 0.15% 摩擦後的淨 R:R ≥ 1.0」為門檻，並設 TP1 最小距離 ≥ 摩擦成本 × 3。
   驗收：tp1 出場 avg r_multiple ≥ +0.8；tp1 淨虧比例 <5%；打平勝率降至 ≤55%。

3. **重新檢討 rr_grade 在等級判定中的角色**
   依據：rr_grade=good 勝率顯著更低（22.0% vs 34.6%，z=-2.36）；rr[2.0,3.0) 桶勝率僅 17.4%；全體 mfe_r≥1.0 僅 18.4%——TP 掛遠換不到命中率。名目 R:R 高不應加分。
   驗收：重跑後 A 級勝率不再顯著低於 B 級；A 級 n 不塌縮至 <30。（注意：tier 間期望值差異目前不顯著，驗收以勝率與 CI 為準，避免拿雜訊當改進。）

### P1（訊號 edge 與機制校準）

4. **改善進場時機**：Sweep 確認後不立即市價進場，改等回踩結構區 limit 進場或加一根確認棒。
   依據：獲利單 40.1% 曾浮虧 ≥0.5R；零摩擦下仍無正 edge。
   驗收（關鍵判準）：`--fee 0 --slippage 0` 口徑的 gross expectancy 轉正；獲利單 mae_r 中位 ≤0.3；淨勝率 ≥40%。

5. **結構區去重取代時間冷卻**：同一 sweep/OB 結構只發一次訊號。
   依據：59.6% 觸發被冷卻壓抑、中位間隔 45–50 分鐘、最短 5 分鐘（冷卻一過立即重觸發）。
   驗收：5m 密度 ≤8 筆/天、中位間隔 >90 分鐘、per-signal 期望值優於基準。

6. **驗證機制校準**：(a) `simulate_outcome` 增加 `--exit-mode tp2_partial`（TP1 平 50% + SL 移保本奔 TP2）並列兩口徑；(b) 同 bar 同觸「樂觀判 TP」敏感度口徑，為結論定上界；(c) 報告固定輸出各 tier 期望值 95% CI 與 tier 單調性檢定，作為每次改動的標準回歸門檻。
   注意：rr_ratio 以 TP1 計（非 TP2），1.08→0.657 的落差來自滑價——分批出場是敏感度校準，預期只小幅改善、不會翻正。

### P2（框架性實驗）

7. **放大目標尺度對抗摩擦**：同幣種 5m（加 SL 距離下限 ≥0.4%）vs 15m vs 30m 對照；`--fee 0.02` 模擬 maker 費率敏感度。幣種組合（SOL 型高波動）是同等級的槓桿——SOL_5m（PF 0.39）優於兩個 15m 配置。
   驗收：至少一組配置 PF ≥ 0.8 且密度 ≥2 筆/天。
8. **清理死參數**：max_hold 下修（p95 持倉僅 11 根）；E 級（0 筆）與 rr_grade=caution（21 筆）的定義與實際分佈脫節，需重整等級空間。

## 四、2026-07-11 進度更新：P0 修復 + 低摩擦假設空間研究

### P0-1 修復完成（root cause 已證實並修復）

三個 bug 兩個根因，均以真實數據證實後修復（回歸測試 `test_precision_label.py` 5/5 通過）：

1. **`calculate_atr` 的 `round(atr, 2)`**（`app_v3.py:772`）：DOGE 原始 ATR ≈ 0.00013、XRP ≈ 0.0018，捨入後 **100% 歸零** → 觸發全管線 `atr <= 0` 防衛 → DOGE 永無訊號；XRP 只在 ATR ≥ 0.005 的尖峰倖存（捨入成 0.01，放大最多 5.8 倍）→ SL 尺度異常。**修復**：全部價格尺度的捨入 2 位 → 8 位（Binance 原生精度），涵蓋 ATR / EMA / MACD / BB / SL / TP / sweep depth。
2. **`determine_signal_label` 無時近性過濾**：`detect_liquidity_sweep` 掃全窗口 20 個 swing point，實測 BTC 651 個窗口 **100% sweeps 非空** → `if sweeps:` 永遠短路。**修復**：新增 `current_index` 參數，只採計近 10 根 bar 內的 sweep。

驗收結果（5m × 5000 根重跑）：DOGE 0 → **319 筆**（18.4/天）；XRP 9 → **313 筆**、SL 距離中位 1.105% → **0.254%**；label 1 類 → **6 類全出現**（4 類 n≥30）。

注意：`calc_structure_score` 的 sweep 計分（`app_v3.py:1496`）有同樣的無時近性問題，本次未動（屬計分語義變更，歸入 P0-3 範疇）。舊版 `calculate_stop_loss_take_profit`（`app_v3.py:941`）為死代碼，未觸碰。

### 低摩擦假設空間研究（4,435 筆事件，5 幣種 × 4 週期）

**週期單調性確立**（taker 0.1% 口徑）：5m PF 0.25 → 15m 0.39 → 30m 0.63 → 1h 0.73。摩擦佔比隨目標距離放大而下降，方向與假設完全一致。

## 五、擴大樣本：30m/1h 正期望假設被推翻（決定性）

為驗證上節第 2 點的「A 級正期望」，將樣本擴大：8 幣種（BTC/ETH/SOL/BNB/XRP/DOGE/LINK/ADA）× 10000 根，A 級樣本從 ~25–29 筆擴至 130–155 筆。數據：`backtest_results/research_20260711/expand_{30m,1h}.json`。

**結果：先前的正期望點估計沒有撐過樣本擴大，全部回歸零/負。**

| 切片（maker 0.02%） | 小樣本 | 擴大後 | 95% CI |
|---|---|---|---|
| 1h A 級 | +0.345R (n=25) | **+0.026R** (n=155) | [-0.19, +0.24] 含零 |
| 30m A 級 | +0.167R (n=29) | **-0.168R** (n=130) | [-0.41, +0.08] 含零 |

判讀：
- 這是典型的**小樣本假象**——n=25 的 +0.345R 是雜訊，樣本一足就回歸至零。
- 擴大樣本後（30m/1h 各約 5,000 筆事件），**唯一 CI 排除零的切片全是 B/C 級的負期望**（如 1h B 級 maker ExpR -0.085，CI[-0.12, -0.05]）。沒有任何等級在任何週期/費率下有統計確立的正期望。
- 時段穩定性檢查：1h A 級最近 1/4 時段點估計 +0.322R，但 n=36、CI ±0.427，仍是雜訊，不構成「近期行情較好」的證據。

**最終結論：SMC 結構訊號在 K 線層面（5m 到 1h）沒有可統計確立的 edge。** 這與外部策略研究一致（見下節）——已收盤 K 線在數分鐘到一小時視野內的資訊已被市場定價，真正的 scalping edge 在微觀結構（L2 orderbook / 逐筆成交），非現有 5m K 線 + 純 Python REST 架構所能承載。

## 六、外部策略研究（deep-research，24 來源 / 22 條經三票查證）

2026-07-11 執行的 deep-research workflow：5 個搜尋角度 → 24 個來源（含 8 篇 primary 學術/官方）→ 117 條主張 → 25 條進入 3 票對抗性查證 → **22 條確認、3 條駁回**。以下綜合按策略家族排列，標註證據來源與投票。

### 各策略家族的 edge 證據地圖

| 策略家族 | edge 證據強度 | 關鍵數據需求 | 費率下可行性 |
|---|---|---|---|
| **Order flow（日/週頻）** | 強（peer-reviewed） | 逐筆成交聚合 | ML long-only 日頻 alpha 0.81%、Sharpe 1.88、**break-even 成本 1.02%/日**（遠高於 0.1% taker） |
| **Orderbook imbalance（秒級）** | 中（實證但微弱） | **L2 orderbook（100ms–1s）** | taker 費後僅中小型幣顯著，BTC/LTC 不顯著 |
| **Market making（造市）** | 強但依賴返佣 | **tick L2 + 佇列/延遲模型** | **僅在 0.005% maker 返佣下成立**；每筆報酬 0.004–0.014%，taker 費率下完全不可行 |
| **技術規則 / 動量突破（K線）** | 弱且 regime-dependent | K 線 | 無無條件 edge；毛報酬是上界，費後常消失 |
| **資金費率套利** | 被高估（非「免費錢」） | REST（資金費率）+ 現貨/永續 | ~17% 標的價差 ≥20bps，但費用+價差反轉侵蝕多數機會 |
| **SMC / ICT 結構** | 無學術實證 | K 線 | 被批評為事後不可證偽；我們 4,435 筆是罕見的嚴格檢驗，證實 5m–1h 無 edge |

### 對我們最關鍵的三條查證結論

1. **微觀結構 edge 存在，但在秒級以下、需要 L2 資料**（3-0）：LOB 方向預測 100ms 準確率 ~0.53（近乎隨機），500ms–1s 才升到 0.65–0.73；Coinbase ETHUSD 的 OBI 在 ~10 秒最強、之後衰減。**這條直接解釋我們 5m K 線為何零 edge——訊號存在的時間尺度比我們的取樣粒度細了兩個數量級。**

2. **造市是 crypto 唯一在所有市場情境都正 alpha 的家族**（Hummingbot pure MM，3-0），**但明確依賴 0.005% 頂級 maker 返佣**（3-0）——每筆報酬 0.004–0.014%，比散戶 taker 費率小一個數量級。散戶拿不到返佣（BNB 25% 折扣把現貨費率降到 0.075% 的說法被 **0-3 駁回**），這條路對我們封閉。

3. **order flow 在日/週頻有 peer-reviewed 的強 edge**（3-0：日頻 alpha 0.81%、break-even 成本 1.02%/日）——注意這是**日頻換手、逐筆成交聚合**，不是 scalping。這暗示若真要用現有 REST 架構找 edge，方向是「日頻 order flow 因子」而非任何分鐘級訊號。

### 被駁回的主張（避免過度悲觀）

- 「資金費率套利 12/20 虧損、Sharpe -7.40 一律負」被 **1-2 駁回**——「非免費錢」成立，但「一律負」證據不足。資金費率採集仍是灰色地帶，未被證偽，只是沒有想像中好賺。
- 「order flow edge 必須秒級 tick、5m K 線抓不到」被 **1-2 駁回**——因為 order flow 在日/週頻同樣有效（見上），並非只能秒級。

## 七、路線建議（基於自有數據 + 外部研究）

1. **5m K 線 scalping 正式證偽**——內部 4,435 筆 + 外部微觀結構文獻雙重佐證，停止調參。
2. **30m/1h SMC 也無確立 edge**——擴大樣本後點估計回歸零，不值得做成產品。
3. **現架構（REST + 純 Python）唯一有學術支撐的方向：日頻 order flow 因子**（買賣量聚合），break-even 成本 1.02%/日遠高於費率——但這是波段/因子策略，不是 scalping，且需重新設計訊號。
4. **真 scalping / 造市需要 L2 WebSocket + 返佣資格**——技術與費率門檻都在現架構之外，不建議。
5. **資金費率採集**可作為低風險探索方向（REST 可做、delta 中性），但需自行驗證，非穩賺。
