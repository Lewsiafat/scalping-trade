# 分析流程文件設計

**日期**: 2026-03-16
**目標**: 建立兩份文件，完整釐清系統的分析流程、判斷邏輯與組織架構

## 背景

目前系統（v4.2.1）的分析流程涵蓋 SMC 引擎、三維評分、兩階段信號、動態 SL/TP 等多個環節，但缺乏統一的文件讓使用者與開發者理解完整流程。需要兩份針對不同讀者的文件。

## 設計決策

- **兩份獨立文件**：交易者與開發者需求差異大，分開更清晰
- **混合式結構**：交易者文件用流程導向（建立端到端理解），開發者文件用模組導向（方便查閱維護）
- **完全透明**：交易者文件公開所有權重、門檻、公式，讓使用者能自行驗證判斷
- **語言**：全繁體中文，技術術語保留英文原文
- **存放位置**：`docs/trading-guide.md` + `docs/developer-guide.md`

## 文件一：`docs/trading-guide.md` — 交易者指南

流程導向，從按下分析到看到結果完整走一遍。

### 章節結構

#### 1. 總覽
- 系統定位（輔助判斷，非自動交易）
- 端到端 Mermaid 流程圖總覽全貌

#### 2. 數據取得與驗證
- Binance 5m K 線 150 根 = 12.5 小時數據窗口
- 驗證規則：最少 50 根、零成交量檢查、時間戳連續性、異常波動偵測

#### 3. SMC 引擎 — 市場結構分析
沿流程依序介紹五個元件：

- **Swing Points（擺動點）**：n=3 雙窗口、保留最近 20 個
- **BOS（突破結構）**：收盤價突破判定
- **Order Blocks（訂單塊）**：反向蠟燭回溯、最多 5 個、失效條件
- **FVG（公平價值缺口）**：三根 K 線缺口、填充率 < 50% 有效、最多 3 個
- **Liquidity Sweep（流動性掃蕩）**：三級分類（Full/Partial/Near）、深度門檻 ATR×0.5

每個元件附示意說明，解釋對交易的意義。

#### 4. 三維評分系統
- 複合分數公式：`Trend × 0.35 + Structure × 0.40 + Momentum × 0.25`
- **趨勢分數**（0-100）：BOS ±30、MTF +25/-10、EMA ±15、Price vs EMA ±10、BB ±10
- **結構分數**（0-100）：OB 進入 +30、OB 接近 +20、趨勢對齊 +15、FVG +15/+10、Sweep +25/+15/+8、深度合理 +10、過深 -10、已測試 -15
- **動能分數**（0-100）：RSI 反轉/延續、RSI 背離 +15、MACD 翻轉/延續、Stochastic 交叉、成交量 +15/-10、Taker Buy +10
- 品質分數換算：avg(三維) / 20，範圍 0-5

#### 5. 兩階段信號機制
- **預警（Pre-Alert）**：觸發條件（OB/Swing ≤ ATR×0.5、FVG 內部/≤ ATR×0.25）、6 根 K 線到期
- **確認信號**：四大條件（預警已觸發 + 三維門檻 + 複合分數 ≥ 45/55 + R:R ≥ 1.0）、3 根 K 線到期
- 信號強度：normal（≥ 45）vs strong（≥ 55）
- 信號標籤優先序：Sweep 確認 > OB 反彈/壓力 > FVG 支撐/阻力 > 指標共振

#### 6. 動態止損止盈（SL/TP）
- 結構錨定邏輯：OB → Swing → ATR 預設
- ATR 夾鉗範圍：1.0×ATR ~ 2.5×ATR
- TP1/TP2 計算與最小距離
- R:R 分級：< 0.7 拒絕、0.7-1.0 降級預警、≥ 1.0 確認、≥ 1.5 優質
- 完整公式展示

#### 7. MTF（多時間框架）確認
- 15m 作為確認時間框架
- 如何影響趨勢分數（+25 對齊 / -10 衝突）

#### 8. 時間與有效性
- 數據窗口：12.5 小時的意義與限制
- 指標收斂時間：MACD(26) 最慢，但 150 根已足夠
- SMC 結構品質與市況關係：盤整期結構稀少 → 分數偏低是正常的
- 信號生命週期：預警 30 分鐘（6 根）、確認 15 分鐘（3 根）到期
- Auto-refresh 頻率：10 秒預設的意義，信號不會永遠存在
- 最佳使用時機：波動活躍時段結構更豐富、分析更可靠
- 多人使用：簡述共用狀態不影響計算結果

#### 9. 如何解讀分析結果
- 對照 UI 各區域說明各數值的意義
- 常見情境範例：強買入信號、預警但未確認、被 R:R 拒絕

## 文件二：`docs/developer-guide.md` — 開發者指南

模組導向，方便查閱與維護。

### 章節結構

#### 1. 架構總覽
- 單檔 monolith 設計：Python 後端 + 嵌入式前端
- 類別關係圖（Mermaid class diagram）
- 請求生命週期簡圖

#### 2. 核心模組詳解
- **ScalpingHandler** — HTTP 路由、端點對應表
- **ScalpingAnalyzerPro** — 靜態方法引擎、方法清單與職責
- **SnapshotManager** — 快照 CRUD、JSON 持久化
- **SymbolManager** — 交易對管理、Binance 驗證
- **AlertManager** — 警報類型、觸發邏輯、cooldown

#### 3. 數據層
- `fetch_with_retry()` — 重試策略、錯誤分類
- `fetch_klines_cached()` — MTF 快取機制
- `validate_kline_data()` — 驗證規則與警告
- 資料檔案格式：snapshots.json、custom_symbols.json、alerts.json

#### 4. SMC 引擎
- 五個方法的輸入/輸出資料結構
- 方法間的依賴鏈：Swing → BOS → OB/FVG/Sweep
- 各方法的保留數量上限與理由

#### 5. 評分與信號系統
- 三維評分：各元件權重表、raw → 正規化邏輯
- 信號判定：門檻矩陣、狀態機轉換
- SL/TP：錨定優先序、ATR 夾鉗、R:R 分級

#### 6. 前端架構
- HTML_PAGE 嵌入結構
- i18n 機制：`data-i18n` + `applyLang()` + `translateAction()`
- 圖表：TradingView Lightweight Charts 整合
- 狀態持久化：localStorage 使用的 key

#### 7. 設計決策
- 為什麼 Structure 權重 0.40 最高
- 為什麼 R:R < 0.7 直接拒絕
- 為什麼用兩階段而非直接出信號
- 為什麼 Sweep 分三級
- 為什麼單檔架構而非拆分模組
- 並發與多使用者：單執行緒模型、全域狀態影響

#### 8. 擴展指南
- 新增技術指標的步驟
- 修改評分權重的注意事項
- 新增 API 端點的流程
- 新增 SMC 元件的整合點
- 新增前端 i18n key 的步驟
